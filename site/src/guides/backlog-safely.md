# Run a backlog safely

## What it is

This guide runs a backlog with the least risk to your repository and to your budget.

## Steps

1. Open a chat in the repository. Attach `backlog.md` with the plus button, or describe the work in a message. Give each task one heading, and say what done means. Do not list files. Sentinel finds the scope.
2. Start with Plan only. Read the plan. Check the scopes, the hidden dependencies, the contradictions, and any task that claims to be done.
3. Answer each decision. Pick one of two contradicting tasks, or skip both. No answer skips both and records a Contradiction.
4. Set the cap and the permission mode. Keep the Brain on read-only for live runs.
5. Watch the stream and the budget. At 70% no new tasks start. At 95% the workers stop.
6. Approve the file requests that make sense. Deny the rest.
7. Read each verdict. Trust only VERIFIED. A VERIFIED task has a passing suite, a new test, and a review by a different model. Quality notes are warnings.
